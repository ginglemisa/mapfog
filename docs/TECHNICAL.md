# MapFog 技術文件

> 給開發者看的完整說明。一般使用方式請看 [README](../README.md)。

免安裝的繁體中文 TRPG 地圖、戰爭迷霧、Token 與先攻管理工具。GM 與玩家有各自的瀏覽器畫面。

## 使用方式

在本機啟動靜態網站伺服器（瀏覽器直接開啟 `file://` 可能讓某些功能失效）：

```sh
python -m http.server 8765
```

開啟 `http://127.0.0.1:8765/`，再選擇 GM 或玩家入口。在 Windows 上也可執行 `start-server.bat`（會開在同一個網址）。

首頁按「GM 控制台」會先跳出模式選擇：

| 選項 | 開啟的網址 | 說明 |
|---|---|---|
| 快速使用 | `gm.html` | 不分房間，直接開啟 |
| 單機分房 `olroom` | `gm.html?olroom=輸入的名稱` | 同一台電腦分房暫存 |
| 跨裝置（網路）`room` | `gm.html?room=輸入的名稱` | 名稱需 8–10 個字元（英文字母、數字、`-`） |
| 區域網路 `lanroom` | `gm.html?lanroom=輸入的名稱` | 英文字母、數字、`-`、`_`；首頁不是由 LAN 伺服器提供時會提醒先執行 `start-lan-server.bat` |

名稱格式不符時會在輸入框下方說明，不會開啟；輸入過的名稱會記在這台裝置，下次自動帶入。按住 Ctrl（或用滑鼠中鍵）點「GM 控制台」則照舊直接開 `gm.html`。

- `gm.html`：GM 控制台
- `pl.html`：玩家畫面
- `?room=房間名`：支援同步服務時，共用的遠端房間代號（見首頁說明）
- `?olroom=房間名`：本機分房暫存；並非不同裝置間的連線方式
- `?lanroom=房間名`：LAN 區域網路房間，同一個 Wi-Fi 或手機熱點下的裝置不需網際網路即可同步（見下方「LAN 模式」）

三種參數只能擇一。網址同時帶兩種以上（例如 `?room=a&lanroom=b`）時，畫面會顯示「網址同時包含多種同步模式」並停止同步，提供只保留其中一種的連結，不會偷偷選一個，也不會同時開兩個同步通道。

## LAN 模式（區域網路、不需網際網路）

GM 筆電執行 MapFog LAN 伺服器，同一個 Wi-Fi 分享器或 Android 手機熱點下的玩家手機、平板用瀏覽器加入。地圖、迷霧、Token、格線、先攻與擲骰都經由 GM 筆電同步，**完全不連 Firebase、Google、Cloudflare 或任何外部網站**。

```
Android 手機熱點（或 Wi-Fi 分享器）
 ├─ GM 筆電：執行 start-lan-server.bat，開 gm.html?lanroom=mygame01
 ├─ 玩家手機 A：掃 QR Code → http://192.168.43.100:8765/pl.html?lanroom=mygame01
 └─ 玩家平板 B：同上
```

- 伺服器（`lan-server.js`，Node.js）同時提供網頁檔案、圖片下載與 WebSocket 同步，預設 port **8765**，監聽 `0.0.0.0`。
- 連線位址由網頁目前的網址決定（`ws://目前的主機:port/lan-ws`），不寫死 IP。
- 房間狀態以伺服器為準，存在 GM 筆電的硬碟；伺服器重新啟動後自動恢復。
- `room`、`olroom` 的行為不變；LAN 房間的瀏覽器暫存使用獨立名稱 `mapfog.lanroom.房間名.`。

### 第一次安裝（Windows）

1. 到 <https://nodejs.org/> 下載 **LTS** 版安裝程式，一路「下一步」安裝（需要網路，只要一次）。
2. 在 MapFog 資料夾按兩下 `start-lan-server.bat`。第一次會自動執行 `npm ci` 安裝套件（`ws`，需要網路，只要一次）；之後啟動完全不需要網路。
   - 也可以自己在資料夾開「終端機」執行 `npm ci --omit=dev`，再執行 `node lan-server.js`。
3. Windows 防火牆跳出「是否允許 Node.js 存取網路」時，勾選 **私人網路**（家用／公司網路）並按「允許存取」。
   - 不小心按了取消：開「Windows 安全性 → 防火牆與網路保護 → 允許應用程式通過防火牆」，找到 **Node.js JavaScript Runtime**，勾選「私人」。
   - 筆電目前連的網路若被 Windows 判定為「公用網路」，防火牆預設會擋住其他裝置。請到「設定 → 網路和網際網路 → Wi-Fi → 這個網路的內容」把「網路設定檔類型」改成 **私人**，或在上一步同時勾選「公用」（只建議在自己的熱點這樣做）。

### start-lan-server.bat 使用方式

按兩下即可。視窗會顯示：

```
 GM 在這台電腦開啟：
   http://127.0.0.1:8765/gm.html?lanroom=mygame01
 其他裝置（同一個 Wi-Fi／手機熱點）可用：
   http://192.168.43.100:8765/pl.html?lanroom=mygame01   [Wi-Fi]
 GM 管理金鑰：ABCD-EFGH-JKLM
 房間資料：C:\...\mapfog\lan-data
```

- 把 `mygame01` 換成自己想要的房間名稱（英文字母、數字、`-`、`_`，1–64 個字元，大小寫不同視為不同房間）。同一台伺服器可以同時開好幾個房間，資料互不干擾。
- 換 port：在命令列執行 `set MAPFOG_PORT=8766` 後再執行 bat，或 `node lan-server.js --port 8766`。8765 也是 `start-server.bat` 的 port，兩者不能同時開。
- 按 **Ctrl+C** 停止（會先把房間資料寫入硬碟），再關掉視窗。
- 其他選項：`node lan-server.js --help`（`--data` 指定資料夾、`--admin-key` 指定金鑰、`--no-local-gm` 本機也要輸入金鑰）。
- 原本的 `start-server.bat`（單機、Python）照常可用，與 LAN 模式無關。

### GM 權限（管理金鑰）

- 伺服器第一次啟動時產生 **GM 管理金鑰**，顯示在伺服器視窗，並存在 `lan-data/admin-key.txt`。
- 在 **GM 筆電本機**開 `gm.html?lanroom=…`（不論用 `127.0.0.1` 還是筆電自己的區網 IP）會自動取得 GM 權限並記住金鑰，不用輸入。
- 用**其他裝置**（例如 GM 的平板）開 `gm.html` 時會跳出輸入框，輸入伺服器視窗顯示的金鑰（大小寫、`-` 可省略）。輸入框被關掉時，右下角會顯示「需要 GM 管理金鑰」，重新整理即可再輸入。
- 玩家直接開 `gm.html`、改網頁程式、偽造 `sourceRole: "gm"` 或自己送 WebSocket 訊息都拿不到 GM 權限：所有權限都由伺服器依連線身分判斷。
- 玩家網址與 QR Code 不包含任何金鑰。想換金鑰：停止伺服器、刪掉 `lan-data/admin-key.txt` 再啟動。

### 一般 Wi-Fi 分享器

1. GM 筆電與所有玩家裝置連到同一台分享器（同一個 SSID；2.4G／5G 分開的分享器通常仍是同一個網段，但「訪客網路」不行）。
2. GM 筆電執行 `start-lan-server.bat`，開 `http://127.0.0.1:8765/gm.html?lanroom=mygame01`。
3. 按 GM 工具列原本的「玩家 QR Code」按鈕，玩家掃描加入（見下方流程）。

分享器不必連上網際網路；拔掉對外網路線也能用。

### Android 手機熱點

1. 一支 Android 手機開「行動熱點」，**手機只負責提供 Wi-Fi**，不用安裝任何東西，也不需要行動數據（可以關掉數據或沒有 SIM 卡，熱點仍能讓裝置互連；少數機型關數據會自動關熱點，請保持熱點開啟）。
2. GM 筆電連上這個熱點，再執行 `start-lan-server.bat`。熱點分配的 IP 每次可能不同（常見 `192.168.43.x`、`192.168.x.x`、`10.x.x.x`），**以伺服器視窗顯示的位址為準**；換了熱點請重新產生 QR Code。
3. 玩家手機也連上同一個熱點，掃 GM 的玩家 QR Code。開熱點的那支手機也可以當玩家：用它的瀏覽器開同一個網址即可。

### 連不上時的排查（熱點裝置隔離與其他限制）

| 狀況 | 原因與處理 |
|---|---|
| 玩家開網址一直轉圈、「無法連上這個網站」 | 先在**玩家手機**的瀏覽器開 `http://筆電IP:8765/lan-api/info`：<br>• 打不開 → 網路不通：確認同一個 Wi-Fi／熱點、Windows 防火牆允許私人網路（見上方），且網路設定檔是「私人」。<br>• 打得開 → 網路正常，請確認網址的 port 與房間名稱。 |
| 筆電與手機都連上熱點，但互相連不到 | 部分手機或分享器開啟了 **AP 隔離**／「裝置隔離」／「Client isolation」／「訪客模式」，禁止連線裝置互通。到熱點或分享器設定關閉這個選項；Android 熱點沒有這個選項時換一支手機或改用分享器。 |
| 右下角顯示「無法連線至 LAN 伺服器」 | GM 筆電的伺服器視窗是否還開著？筆電是否進入睡眠（請把電源設定的睡眠關掉）？網址是否是伺服器視窗列出的區網 IP，而不是 `127.0.0.1`／`localhost`？ |
| 伺服器視窗列出好幾個位址 | 筆電同時有有線網路、虛擬網卡（Hyper-V、VirtualBox、WSL）等。選與玩家同一個 Wi-Fi 的那一個（Windows：設定 → 網路和網際網路 → Wi-Fi → 內容 → IPv4 位址）。 |
| 一直顯示「已斷線，正在重新連線」 | 手機切到背景或螢幕關閉時，瀏覽器可能暫停連線；回到畫面會自動重新連線並補上漏掉的變化。 |
| `無法啟動：連接埠 8765 已被其他程式使用` | `start-server.bat` 或另一個 LAN 伺服器還開著；關掉，或改用其他 port。 |
| 玩家手機連熱點後自動切回行動數據 | 有些手機發現 Wi-Fi「沒有網際網路」會自動改用行動數據。點選「保持連線／仍要使用此網路」，或暫時關閉行動數據。 |

### QR Code 玩家加入流程

1. GM 用 `gm.html?lanroom=mygame01` 開好房間，按工具列原本的 **玩家 QR Code** 按鈕（不需新增其他入口）。
2. 每次按下都重新讀取目前網址的 `lanroom`，用 `new URL("pl.html", 目前網址)` 建立玩家網址：保留協定、port 與路徑，只留下 `lanroom`（`room`、`olroom` 等參數不會帶過去），也不包含 GM 金鑰。QR Code 與下方可複製的網址是同一個字串。
3. GM 用區網 IP（例如 `http://192.168.43.100:8765/gm.html?lanroom=mygame01`）開啟時，直接產生 `http://192.168.43.100:8765/pl.html?lanroom=mygame01`。
4. GM 用 `127.0.0.1`／`localhost` 開啟時，`localhost` 在其他裝置上指向它們自己，不能放進 QR Code：對話框會向 LAN 伺服器查詢筆電的區網 IPv4 位址清單（`/lan-api/info`）。
   - 只找到一個區網位址：自動選用並提示確認。
   - 有好幾個位址：不猜測，請 GM 從清單選擇；選好的位址會記住，下次沿用。
   - 找不到或查詢失敗：顯示警告並改成手動輸入 IP。
5. 玩家用手機相機掃描 QR Code（或輸入下方網址）即可加入。「複製玩家網址」在區網 http 網址上無法使用剪貼簿 API 時，會改用舊的複製方式；再不行就選取網址請 GM 手動複製。

`room` 模式的 QR Code 行為完全不變。

### 同步規則與衝突處理

LAN 模式沿用 room 模式的所有規則（「GM 是唯一真相」、只送有變的欄位、迷霧 epoch／seq／checkpoint、圖片依雜湊快取），並改由伺服器把關：

- **權限由伺服器驗證**：地圖、迷霧、格線、公開先攻、清除房間、刪除圖片只有 GM 能做。玩家只能移動、縮放、改形狀、刪除**未鎖定**的 token，新增的 token 一律未鎖定，不能改名稱、鎖定、可見度或先攻連結；被拒絕時伺服器把正確的狀態送回，畫面自動改回。
- **鎖定寬限**：GM 鎖定 token 後 10 秒內，仍接受玩家放開時送出的最後位置（不接受大小、形狀）。
- **刪除不復活**：刪除過的 token 會記下，之後晚到的位置更新或新增都會被拒絕。
- **圖片**：先上傳圖片（伺服器檢查雜湊與內容一致）才接受引用它的 token／地圖；同一個 WebSocket 依序處理，玩家拿到 token 時圖片一定已在伺服器上。圖片用一般 HTTP 下載，依雜湊快取。單張上限 12MB（地圖仍沿用 9MB 的自動壓縮），每個房間的圖片總量上限 512MB。
- **私有資料不外流**：先攻只同步名稱與敵友，HP 與先攻值留在 GM 瀏覽器，伺服器也不會存；擲骰顯示的 GM／PL 身分與總和由伺服器依連線計算。
- **斷線期間的修改**：
  - 斷線時的操作依順序排隊，並存進這台裝置的 IndexedDB；**重新整理或關掉分頁後再開，也會在連上時補送**。
  - 補送時的衝突規則：每個目標（地圖、迷霧、格線、每一個 token）只在「斷線期間沒有其他人改過」或「最後修改的就是自己」時才套用；否則**以伺服器為準**，畫面改回伺服器的版本。擦霧紀錄只在迷霧版本（epoch）沒換過時補上。先攻表以 GM 為準，擲骰一律補送。
  - 補送完成後才取得完整房間狀態，所以重新連線後畫面與伺服器一致，不會被舊暫存蓋掉，也不會讓房間被清空。
- **連線狀態**：右下角顯示「LAN 模式・已連線／連線中／已斷線，正在重新連線（第 N 次）」、GM 的在線玩家數、同房間有另一個 GM 時的警告，以及連不上伺服器、需要 GM 金鑰的說明。只看與 LAN 伺服器的連線，沒有網際網路不會被標成離線。斷線後以 0.5 秒起、每次加倍、最多 15 秒的間隔自動重連；另外每 8 秒確認一次伺服器還在，Wi-Fi 斷掉時幾秒內就會發現。

### 資料保存位置與備份

- 預設在 MapFog 資料夾下的 `lan-data/`（可用 `--data` 或環境變數 `MAPFOG_DATA_DIR` 改位置）：
  - `admin-key.txt`：GM 管理金鑰。
  - `rooms/房間名-雜湊/state.json`：地圖、迷霧、格線、先攻、token 等房間狀態；`state.json.bak` 是伺服器上次啟動時的備份。
  - `rooms/房間名-雜湊/images/{雜湊}.txt`：圖片（原樣存放的 dataURL）。
- 寫入方式：變動後約 0.4 秒寫一次，先寫暫存檔再改名（atomic rename），中途斷電也不會留下寫一半的檔案；主檔真的損毀時自動改用 `.bak`。
- **備份**：停止伺服器後複製整個 `lan-data` 資料夾即可；還原時放回原處再啟動。換電腦時連同 MapFog 資料夾一起複製。
- `lan-data/` 已列在 `.gitignore`，不會被提交。

### 已知限制

- **http 區網網址不是「安全來源」**：
  - Service Worker 無法在 `http://192.168.x.x` 啟用，**伺服器關閉時玩家無法重新整理網頁**（開著的頁面不受影響，會自動重連）。LAN 模式不需要 Service Worker 也能正常使用。
  - 剪貼簿 API 無法使用，複製網址改用備援方式。
  - `crypto.randomUUID` 等需要安全來源的 API 都有備援，IndexedDB、Canvas、WebSocket 在 http 區網網址都能正常使用。
- **安全性**：區網內的連線是未加密的 http／ws，同一個 Wi-Fi 的人理論上可以監看流量。任何知道網址的人都能以玩家身分加入；請只在信任的網路（自己的熱點、家用分享器）使用，並設定熱點密碼。伺服器只接受 IP、`localhost` 與本機名稱這類網址（擋下 DNS rebinding），WebSocket 也會檢查 Origin。
- GM 管理金鑰保護 GM 操作，但不是帳號系統；不要把金鑰給玩家。
- 伺服器所在的筆電睡眠或關機時大家都會斷線；團務期間請關閉睡眠。
- 同一台伺服器的房間依名稱區分，玩家只要知道房間名稱就能加入那個房間。
- LAN 房間的本機暫存不會自動清除（跟 olroom 一樣）；可用「清除目前 LAN 房間」清掉伺服器與本機的資料。
- iOS／Android 瀏覽器在背景時可能暫停 WebSocket，回到前景會自動重連並補齊。

### 單機（含 olroom）注意事項

- GM 與玩家畫面必須用**同一個瀏覽器、同一個網址開頭**開啟。`localhost` 與 `127.0.0.1`、不同 port、無痕視窗、不同瀏覽器都會被當成彼此獨立，不會同步，也看不到對方的暫存。
- 地圖、迷霧與 token 暫存在瀏覽器的 IndexedDB（容量遠大於 localStorage），可以為多個 olroom 各自準備地圖。暫存規則與 room 模式相同，見下方「本機暫存與離線」。
- 只開玩家視窗、GM 視窗沒開時，玩家畫面會用同一台電腦上 GM 最後的暫存畫面。
- GM 切換 olroom 後，按地圖設定下方的「玩家畫面切到此房間」，外接螢幕上的玩家畫面就會跟著切換；GM 只是開啟其他 olroom 準備地圖時，玩家畫面不會自動跳過去。
- 清除 olroom 暫存時，開著的同房間玩家畫面會一起重新整理，避免把舊 token 寫回去。
- 只有網址帶 `?room=` 時才會下載 Firebase SDK，離線單機使用不需要網路。

GM 可將先攻表中的名字拖曳到地圖上，建立友方綠底或敵方紅底的白字 token，顯示名稱中第一個英文或中文字元；首字重複時，依序在圖上加上編號，例如「哥、哥1、哥2」。Token 清單則保留完整角色名稱。點擊名字（或以鍵盤 Enter／空白鍵啟用）則放在地圖中央。新 token 可沿用 Token 面板調整大小、形狀與刪除，並同步到玩家畫面；拖曳列上的順位數字仍可調整先攻順序。無論是上傳圖片或由先攻表建立的 token，在 GM 與玩家畫面旋轉地圖時都維持原本方向。

先攻面板的「HP」按鈕可切換 token 上方的血量數字，僅 GM 可見，玩家同步資料不包含 HP。文字依友方／敵方顯示綠色／紅色，選取 token 後可在 Token 設定調整「HP 字體大小」。尚未對應先攻的圖片 token 可按「加入先攻」，由 GM 填寫名稱、先攻與 HP，並選擇敵／友。

## 圖片自動處理（第 2 階段）

上傳時自動處理，不需要先用其他軟體轉檔。`olroom`、`room` 和不帶房間的本機畫面共用同一套圖片規則。

- **Token**：GM／玩家上傳的圖片會置中裁成正方形，輸出 **256×256 WebP，品質 0.85**。先攻表建立的文字 token 也使用相同尺寸與格式，敵／友顏色、名稱編號、HP 與鎖定規則不變。
- **地圖尺寸**：長邊最多 **4096px**、總像素最多 **16,777,216**，超過就等比例縮小。例如 8000×6000 → 4096×3072（51.2%）。不會先建立原始尺寸的大畫布；暫用畫布用完會釋放。
- **地圖格式**：一般轉成 WebP，品質 0.85；原檔是 JPG 或 WebP、尺寸符合上限，且檔案**小於 5MB**時，直接保留原始檔案內容。
- **Safari 備用流程**：檢查輸出字串的實際格式。不支援 WebP 輸出的裝置，token 與需要轉檔的地圖改用 PNG；透明背景保留。支援 WebP 的 Safari 仍使用 WebP。PNG 備用檔可能比 WebP 大，甚至比原 PNG 大。
- **room 額外容量限制**：包含 base64 的完整 dataURL 必須**小於 9MB**。WebP 先將品質降至 0.70、0.55，仍太大就每次將寬、高縮至 75%；PNG 不降品質，直接縮小尺寸。包含第一次輸出，最多嘗試 **6 次**。仍超限就顯示原因，不套用也不傳送這張圖，可縮小原圖後重試。
- **處理提示**：地圖設定內顯示「正在處理地圖…」，完成後顯示原始／結果尺寸、格式、容量與縮放百分比；保留原檔也會明確告知。處理中暫停選取下一張地圖，完成或失敗後可重新選取同一檔案。
- **匯出與亮度**：地圖、迷霧與格線畫布都使用處理後的尺寸；同步與暫存也使用處理後的圖片。「另存調整後地圖」與格線匯出沿用 JPG 格式，輸出處理後尺寸並套用本機亮度／對比／飽和度。亮度仍不會同步，**格線由 GM 自行重新調整**。

容量一律以十進位計算：1KB＝1,000 bytes、1MB＝1,000,000 bytes。結果中的圖片容量是檔案本身大小；room 額外顯示的「傳送資料」包含 base64，通常比圖片檔案大約三分之一。處理完成表示圖片已在本機準備好，是否送達玩家仍取決於連線與 Firebase 房間權限。

例如：`已自動縮小：8000×6000 PNG 24MB → 4096×3072 WebP 2.1MB（縮放 51.2%；room 傳送資料 2.8MB）`。實際容量會依圖片細節與裝置而不同。

## 同步規則（GM 是唯一真相）

olroom 與 room 兩種模式套用同一套規則：

- **選取只在自己的畫面**：在哪個畫面點選 token，只影響那個畫面。玩家點選 token 不會改到 GM 的選取，GM 也不會因此改到或刪到錯的 token。
- **只送有變的部分**：移動 token 只送位置，調大小只送大小。GM 和玩家同時拖不同的 token，不會互相蓋掉。
  - 新增 token 時才送出完整資料；圖片只送「圖片雜湊」，圖片本身另外存放（見「本機暫存與離線」）。
  - 刪除就是整顆移除。刪除之後才晚到的位置更新，不會把 token 救回來。
- **每筆 token 變更都標記來源**（`sourceRole: "gm"` 或 `"player"`），GM 畫面靠它判斷要不要接受。

### Token 鎖定

| | 鎖定（🔒） | 未鎖定（🔓） |
|---|---|---|
| GM | 全部操作 | 全部操作 |
| 玩家 | 完全不能操作：拖不動、點下去會直接拖動地圖，大小／形狀／移除按鈕停用 | 可以移動、調大小、改形狀、刪除（不論是誰建立的） |

- 預設值：GM 上傳的 token、從先攻表拖出來的 token 預設**鎖定**；玩家上傳的 token 預設**未鎖定**。把 token「加入先攻」不會改變鎖定狀態。
- GM 的 Token 面板：「🔒 已鎖定／🔓 未鎖定」按鈕可切換目前選取的 token；另有「全部鎖定」「全部解鎖」。下拉清單裡鎖定的 token 前面會有 🔒。
- 兩道防線：
  1. 玩家畫面本身不送出對鎖定 token 的變更。
  2. GM 畫面開著時，若仍收到玩家對鎖定 token 的修改或刪除，會立刻改回 GM 的版本。
- 例外：玩家在鎖定之前就開始拖曳，放開時送出的最後位置，GM 在鎖定後 10 秒內仍會接受。拖到一半被鎖定時，中途的位置不會再送出，只送放開時那一筆。
- GM 不在線時，只剩第 1 道防線（防君子用途已足夠）。

### room 模式的連線狀態

畫面右下角會顯示連線狀態：

- 「已連線」或「已斷線，網路恢復後會自動重新連線」。
- 開頁時連不上（約 4 秒內沒連上，或同步服務載入失敗），而畫面是從本機暫存還原的：顯示紅點「離線中，顯示的是暫存畫面；恢復連線後會自動更新」。
- 同步服務（Firebase SDK）載入失敗時，每 10 秒自動重試一次，網路恢復時也會立刻重試，不必手動重新整理。
- 房間被 Firebase 規則拒絕時（多半是房間名稱不是 8–10 個字元），顯示紅點「無法使用房間「名稱」：Firebase 拒絕存取。房間名稱需為 8–10 個字元（英文字母、數字或 -），請換一個名稱。」這時完全不會同步，請改用符合規則的名稱。
- GM 畫面另外顯示「玩家 N 人在線」。
- 同一個 room 同時開了兩個 GM 畫面時，兩邊都會出現警告。

斷線期間的操作會在恢復連線後自動送出，詳見「本機暫存與離線」。

### room 模式的 Firebase 資料位置

全部資料都在 `rooms/{room}/` 底下，資料庫規則需要允許這些路徑讀寫：

| 位置 | 內容 |
|---|---|
| `images/{雜湊}` | 圖片本身 `{ dataUrl, kind }`，kind 是 `map`、`token` 或 `fog`（迷霧 checkpoint）。只在本機沒有這張圖時，才單獨下載一次。 |
| `imageIndex/{雜湊}` | 圖片清單 `{ kind, bytes, addedAt }`，很小；GM 用它找出沒人用的圖片。 |
| `map` | 目前地圖 `{ hash, width, height }`，不放圖片。 |
| `fog` | 迷霧狀態 `{ epoch, base, checkpointHash, mapHash, width, height }`。 |
| `fogBatches/{epoch}/{序號}` | 擦霧紀錄，每次放開滑鼠／手指一筆，序號由 GM 依序編號。 |
| `token/tokensById/{tokenId}` | 每顆 token 一個節點，記 `imageHash`、位置、大小、鎖定等。 |
| `events/diceRoll` | 擲骰事件，只保留最近 100 筆。 |
| `presence/{連線代號}` | 目前在線的畫面 `{ role, connectedAt }`，斷線時自動移除。 |
| `gridSettings`、`initiative` | 格線與先攻。 |

迷霧的規則：

- `base` 是迷霧底圖：`covered`（全蓋）、`revealed`（全開）或 `checkpoint`（`checkpointHash` 指向的迷霧圖片）。
- 底圖之上依序號套用 `fogBatches/{epoch}` 的擦霧紀錄。
- GM 換地圖、按「重設迷霧」「全部顯示」時，換一個新的 `epoch`，舊的擦霧紀錄一併刪除。
- 同一個 epoch 累積 200 筆後，GM 把目前迷霧存成 checkpoint 圖片並換新 epoch，玩家重新進房就不必重播全部紀錄。
- 舊版的 `events/drawBatch`、`events/fogCommand`、`fogHistory`、`snapshot` 已不再使用。

最簡單、只用來分房間的規則範例：

```json
{
  "rules": {
    "rooms": {
      "$room": {
        ".read": true,
        ".write": true
      }
    }
  }
}
```

## 本機暫存與離線（第 3 階段）

GM 與玩家、olroom 與 room 都使用同一套本機暫存（瀏覽器的 IndexedDB）。

### 存了什麼

- **圖片**：依「房間名稱＋圖片雜湊」存放。收到地圖或 token 時，本機已有同一個雜湊的圖片就直接使用，不再下載。
- **最後看到的畫面**：地圖雜湊、迷霧畫布、迷霧進度（epoch 與已套用到第幾號擦霧）、token 位置、格線。GM 與玩家畫面各存一份。
- 畫面變動停下約 1.5 秒後寫入；畫迷霧或拖 token 時先不寫。切到背景或關閉分頁時會立刻寫入（iPad Safari 關分頁常常不觸發一般的關閉事件，所以另外處理）。

### 開頁面時

1. 先立刻顯示本機暫存的畫面。
2. 再跟 Firebase（room）或 GM 視窗（olroom）比對：
   - 地圖雜湊一樣就不下載、不重畫。
   - 迷霧是同一個 epoch，只下載暫存之後新增的擦霧；epoch 不同（GM 重設、全開或壓縮過）才重新載入底圖。
   - 暫存裡有、房間裡已被刪掉的 token 會移除。
   - GM 已清除這個房間時，玩家畫面會清掉暫存並重新整理成空白。
3. 開啟網頁的 Console（F12）可以看到每張圖片是「從本機暫存載入」還是「從 Firebase 下載（xx MB）」。

### 斷線與離線

- **開著頁面時斷線**：畫面維持原樣。恢復連線後，Firebase 會把斷線期間漏掉的擦霧與 token 變化依序補上。
- **斷網後重新整理**：網頁用 Service Worker（`sw.js`）把網頁檔案與 Firebase SDK 存一份在裝置上，斷網時也能開啟，並顯示暫存畫面與離線提示。有網路時一律先抓最新版本，改了程式不會卡在舊版。
  - 只有 `https://` 網址或 `127.0.0.1`／`localhost` 能使用 Service Worker。用 `http://192.168.x.x` 這類區網位址時，斷網後重新整理會看到瀏覽器的「沒有網路」頁面；開著頁面時斷線不受影響。
  - 要先在有網路時開過一次網頁，裝置上才有存檔。
- **GM 斷線期間的操作**：
  - 頁面開著、只是暫時斷線：由 Firebase SDK 排隊，恢復連線後依原本順序送出。擦霧序號由 GM 自己編號，不會因為排隊而跳號或重複。
  - 同步服務還沒載入（例如斷網時開啟或重新整理）：GM 的修改會記在本機暫存裡，連上後一次補送（迷霧直接存成一張 checkpoint，token 與格線整筆送出）。中途重新整理也不會遺失。
  - **限制**：頁面開著、SDK 已載入但斷線時，SDK 的排隊只存在記憶體。這時如果 GM **關掉或重新整理分頁**，還沒送出的操作會遺失；恢復連線後畫面以 Firebase 上的內容為準。下一次迷霧壓縮或重設後，GM 與玩家的迷霧會重新一致。
- 玩家斷線期間移動 token 也一樣：頁面開著會自動補送；鎖定與否仍由 GM 判斷。

### 清除沒在用的圖片

- **Firebase**：GM 換新地圖、刪除 token、迷霧重設或壓縮後約 3 秒，GM 畫面會刪除 `images` 中已沒人使用的圖片（地圖、所有 token、迷霧 checkpoint 都沒用到）。剛上傳不到 60 秒的圖片先保留，避免玩家剛上傳、token 還在路上就被刪掉。
- **本機**：換地圖後，會刪掉這個房間已沒在用的本機圖片。超過 30 天沒開過的 room，本機暫存會在開啟其他 room 時自動清除（room 的資料 Firebase 上還有一份）；olroom 只存在本機，不會自動清除。
- 刪圖片只在同一個 room 裡進行。舊 room 不清除仍會占用 Firebase 空間，團後可用「清除目前 room 暫存」清掉。

### Firebase 下載流量估算

假設：一場團 4 張地圖（每張一個 room）、4 位玩家、每人重新整理 2 次、斷線重連 2 次；地圖一般約 3MB（最大 9MB）、每張地圖 8 個 token 約 25KB、進房時累積的擦霧約 0.4MB、遊戲中每人每張地圖即時收到約 0.9MB。

| 項目 | 改動前（一般／最大地圖） | 改動後（一般／最大地圖） |
|---|---|---|
| 第一次進房（16 人次） | 58 MB／154 MB | 58 MB／154 MB |
| 遊戲中即時更新 | 14 MB | 14 MB |
| 重新整理（8 次） | 29 MB／77 MB | 約 0.5～3 MB |
| 斷線重連（8 次） | 0～2 MB | 約 0.2 MB |
| **每場合計** | **約 100 MB／250 MB** | **約 73 MB／170 MB** |
| **每月 10 場** | **約 1.0 GB／2.5 GB** | **約 0.7 GB／1.7 GB** |

- 實測（自動化測試，1800×1200 的 2.07MB 地圖加 2 個 token）：玩家第一次進房約 2.1MB，重新整理約 2.6KB。
- 另有 Firebase 連線與加密本身的額外流量，大約再多 1～3 成。兩者都遠低於免費方案每月 10GB。
- GM 每次重新整理：改動前約 3.6MB，改動後接近 0。

## 手動測試步驟

### A. 同一台電腦、兩個瀏覽器視窗（olroom）

準備：執行 `start-server.bat`。用**同一個瀏覽器**開兩個視窗：

- 視窗 1：`http://127.0.0.1:8765/gm.html?olroom=testroom1`
- 視窗 2：`http://127.0.0.1:8765/pl.html?olroom=testroom1`

步驟：

1. GM 上傳一張地圖，再上傳一張 token 圖片。玩家畫面應出現地圖與 token。
2. **選取不互相影響**：GM 再上傳第二個 token，在 Token 面板選取「Token 1」。到玩家畫面點選另一個 token（或在玩家的 Token 面板下拉選單換一個）。回到 GM：選取的仍是「Token 1」。
3. **鎖定的 token 玩家不能動**：GM 上傳的 token 預設鎖定，GM 下拉清單顯示 🔒。玩家畫面：
   - 拖這個 token 拖不動，滑鼠移上去不會變成手的形狀；拖它其實是在拖地圖。
   - 打開玩家 Token 面板、選這個 token：大小、方形／六角形、移除都是灰色不能按，下方寫「已被 GM 鎖定」。
4. **解鎖後玩家可以操作**：GM 選這個 token，按「🔒 已鎖定（點此解鎖）」，按鈕變成 🔓。玩家畫面：
   - 可以拖動，GM 畫面跟著移動。
   - 調大小、改六角形，GM 畫面跟著變。
   - 按「移除 token」，GM 畫面的 token 也消失。
5. **全部鎖定／全部解鎖**：GM 按「全部鎖定」，清單全部出現 🔒，玩家全部拖不動；按「全部解鎖」，玩家全部可以拖。
6. **拖到一半被鎖定**：把 token 解鎖。玩家按住 token 開始拖（不要放開），GM 按鎖定，玩家繼續拖一下再放開。
   - 預期：GM 畫面的 token 停在玩家放開的位置，不會跳回去。
   - 之後玩家再拖就拖不動。
7. **同時拖不同 token**：解鎖一個 token。GM 拖 A、玩家同時拖 B（可以兩手各用一個滑鼠或觸控板，或快速交替）。放開後兩邊畫面中 A、B 的位置都一樣。
8. **玩家上傳的 token**：玩家上傳一張圖片。GM 清單中沒有 🔒，玩家可以自由拖動。
9. **先攻拖出的 token**：GM 在先攻表新增一位角色，拖到地圖上。GM 清單顯示 🔒，玩家拖不動。按「加入先攻」不會改變鎖定。
10. **重新整理**：玩家視窗按 F5，token 的位置與鎖定狀態都和 GM 一致。

### B. 兩台裝置（room）

準備：先確認 Firebase 資料庫規則允許 `rooms/{room}` 讀寫（見上方範例）。**房間名稱必須是 8–10 個字元**（英文字母、數字或連字號 `-`）；`test1`、`cache1` 這種太短的名稱會被 Firebase 規則拒絕（`permission_denied`），畫面會一直連不上資料，看起來像是同步失敗。

用你平常讓玩家連線的網址開啟：

- 裝置 1（GM）：`…/gm.html?room=testroom1`
- 裝置 2（玩家，例如平板或手機）：`…/pl.html?room=testroom1`

步驟：

1. 兩邊右下角都顯示「● 已連線」，GM 畫面顯示「玩家 1 人在線」。再用第二台裝置開玩家畫面，GM 畫面變成「玩家 2 人在線」。
2. 重做 A 的第 2～9 步，結果應相同。
3. **擦霧不漏接**：GM 用刷子在地圖上快速連續擦霧約 10 秒（很多短筆畫）。玩家畫面**不重新整理**，迷霧形狀應和 GM 一致。
4. **迷霧指令**：GM 連續快速按「全部顯示」「重設迷霧」「全部顯示」。玩家畫面最後是全部顯示。
5. **擲骰不漏接**：玩家連續快速擲骰 20 次（每次點骰子再按擲骰）。GM 的擲骰紀錄 20 次都在；反過來由 GM 擲骰 20 次，玩家那邊也都在。
6. **斷線顯示**：玩家裝置關掉 Wi-Fi。
   - 玩家畫面右下角變成紅點「已斷線」。
   - 約 1 分鐘內 GM 的在線玩家數減 1（Firebase 偵測斷線需要一點時間）。
   - 打開 Wi-Fi，玩家畫面恢復「已連線」，GM 的人數也加回來。
7. **兩個 GM 警告**：在另一個分頁也開 `gm.html?room=testroom1`，兩個 GM 畫面右下角都出現黃色警告。關掉其中一個後，警告消失。
8. **清除 room**：GM 在地圖設定按「清除目前 room 暫存」。鎖定的 token 不會被補回來，玩家畫面的 token 也清空。
9. **房間名稱不符合規則**：開 `…/pl.html?room=test1`（只有 5 個字元）。幾秒內右下角出現紅點「無法使用房間「test1」：Firebase 拒絕存取……請換一個名稱。」GM 畫面開 `…/gm.html?room=test1` 也一樣。改回 `testroom1` 後恢復「已連線」。

### C. 圖片壓縮：同一台電腦、兩個視窗（olroom）

準備以下圖片：1–2MB 的長方形角色照片、8000×6000 PNG 地圖、3000px 且小於 5MB 的 JPG 地圖，以及有透明背景的 PNG 地圖。另可準備符合保留條件的 WebP 地圖。

用同一個瀏覽器、同一個網址開頭開啟：

- GM：`http://127.0.0.1:8765/gm.html?olroom=image-test`
- 玩家：`http://127.0.0.1:8765/pl.html?olroom=image-test`

1. **大 PNG 地圖**：GM 開啟地圖設定，上傳 8000×6000 PNG。應先出現「正在處理地圖…」，完成後顯示 4096×3072、縮放 51.2%，以及實際輸出格式與容量。玩家也應看到同一張地圖；先按「全開迷霧」方便比對。
2. **保留 JPG／WebP**：換成 3000px、小於 5MB 的 JPG。應顯示「已保留原檔」，尺寸不變、縮放 100%、仍為 JPG。符合條件的 WebP 也應保留原檔。PNG 即使很小仍會走轉檔流程。
3. **透明背景**：換成透明 PNG。確認透明部分沒有被填成黑色或白色；如果背景顏色不易辨認，可使用下方的進階檢查。另存 JPG 本來就會將透明部分填白，這不代表上傳透明度遺失。
4. **GM 與玩家 token**：兩邊各上傳一次 1–2MB 的長方形照片。兩邊應看到置中裁切的正方形圖片，沒有被拉長。GM 上傳的預設鎖定，玩家上傳的預設解鎖；解鎖後移動、改大小與形狀仍正常。
5. **先攻文字 token**：新增同名敵人與友方，將名字拖到地圖，或點名字建立。確認紅／綠底白字、重複名稱編號、HP 顯示與鎖定仍正常。先攻與擲骰也各操作一次，確認原有功能可用。
6. **亮度與匯出**：重新載入大 PNG，GM 調亮地圖，玩家亮度應不變。分別用「另存調整後地圖」及格線面板的匯出按鈕下載 JPG，查看圖片資訊：應為 4096×3072；調亮效果應存在，格線匯出包含手動調整好的格線。
7. **還原與重選**：重新整理兩個視窗，地圖與 token 應保留。再選取同一張地圖，應重新出現處理結果。
8. **讀取失敗**：可將一份測試用文字檔副本改名為 `.png` 後上傳。應出現「地圖處理失敗」，舊地圖仍在；接著上傳正常圖片應可成功。

### D. 圖片壓縮：兩台裝置（room）

準備：使用可從兩台裝置開啟的網站網址，以及 Firebase 規則允許的測試房間。`127.0.0.1` 在每台裝置都指向自己，不能讓平板連到筆電；請用平常的網站網址，或同網路下筆電的區域網路位址。若出現 `permission_denied`，先確認房間名稱是 8–10 個字元，再確認該測試房間的規則。

1. 裝置 1 開 `…/gm.html?room=image-test`，裝置 2 開 `…/pl.html?room=image-test`。重做 C 的第 1～6 步；兩台裝置應收到同樣的處理後圖片。
2. **確認 token 流量**：兩邊各上傳一張 1–2MB 照片。在 Firebase Console 的 Realtime Database 資料頁，`rooms/image-test/token/tokensById` 裡的 token 只有 `imageHash`；到 `rooms/image-test/images/{那個雜湊}` 查看 `dataUrl`，應以 `data:image/webp;base64,` 開頭。將**單張圖片節點**匯出 JSON，下載檔案通常只有幾十 KB，而不是原本的 1–2MB。圖片細節會影響容量，PNG 備用輸出可能更大。
3. **確認地圖資料**：在 `rooms/image-test/map` 檢查 `width`、`height`，大地圖應為 4096、3072（若因 9MB 限制繼續縮小，則會更小）。`map.hash` 指向的 `images/{雜湊}/dataUrl` 格式須與 GM 提示一致。完整字串應小於 9,000,000 bytes，可用下方檢查讀取目前地圖的長度。
4. **容量重試**：用細節很多的大 PNG 測試，尤其在不能輸出 WebP 的 Safari。若初次結果太大，應繼續縮小，完成提示會反映最終尺寸；「room 傳送資料」必須小於 9MB。若 6 次後仍不合格，應顯示尚未套用的錯誤，兩邊保留舊地圖。一般圖片可能第一次就合格，不一定能自然觸發失敗分支。
5. **慢速／斷線玩家**：玩家關閉 Wi-Fi，GM 上傳一張新的地圖；玩家恢復連線後，應收到最終處理後圖片。再重新整理玩家頁面，地圖與 token 應能還原。這一步需要實際 Firebase 權限可用。

### E. iPad Safari 實機

1. iPad 作為玩家，筆電作為 GM，以同一個 `room` 連線。iPad 上傳照片 token；筆電應收到 256×256 的圖片。用下方檢查確認實際格式：不支援 WebP 輸出的 Safari 應是 PNG；支援的 Safari 則是 WebP，兩者都正確。
2. 對調角色，iPad 作為 GM，筆電作為玩家。iPad 上傳 8000×6000 PNG；確認出現處理中提示、結果尺寸符合上限。使用 PNG 備用時，結果會寫「此裝置改用 PNG」。接著測試 3000px JPG 保留原檔、透明 PNG，以及先攻文字 token。
3. 連續切換 3～4 張大地圖，縮放、旋轉、擦霧、補霧，開啟格線、先攻、HP 與擲骰，確認頁面沒有白畫面、意外重新載入或關閉。
4. 在 iPad 調整亮度、下載調整後 JPG 與格線 JPG；確認圖片能開啟、尺寸符合縮圖結果，筆電玩家的亮度沒有跟著變。
5. 讓 iPad 保持玩家畫面，GM 載入大圖，確認接收與重新整理也不會造成頁面當掉。記下 iPad 型號與 iPadOS 版本，方便比對不同裝置。

尺寸限制可降低大畫布的風險，但 iPad 的可用記憶體也受型號、其他分頁與原始圖片解碼影響；桌面模擬不能代替上述實機測試。

#### 選用：在筆電檢查收到的圖片

在 GM 或玩家畫面按 F12（或開啟瀏覽器「開發人員工具」），切換到 Console，執行以下內容即可列出圖片資料。這只讀取目前畫面，不會修改房間。iPad 上傳的圖片也可在接收端筆電檢查。

```js
({
  地圖: { 寬: mapCanvas.width, 高: mapCanvas.height,
    格式: currentMapDataUrl.split(";")[0], 傳送bytes: currentMapDataUrl.length,
    左上角透明度: mapCtx.getImageData(0, 0, 1, 1).data[3] },
  Token: Array.from(document.querySelectorAll(".map-token img"), img => ({
    寬: img.naturalWidth, 高: img.naturalHeight,
    格式: img.src.split(";")[0], 傳送bytes: img.src.length
  }))
})
```

Token 寬、高應都是 256；有透明左上角的地圖，其左上角透明度應是 0（完全透明），不透明則為 255。這裡的資料是瀏覽器實際載入的圖片；確認 Firebase 儲存內容請搭配 D 的資料庫檢查。

### F. 本機暫存與離線：同一台電腦、兩個瀏覽器視窗（olroom）

準備：同 A，用同一個瀏覽器開 `gm.html?olroom=cachetest1` 與 `pl.html?olroom=cachetest1`。

1. GM 上傳地圖與 2 個 token，擦掉幾塊迷霧、移動一個 token。玩家畫面一致。
2. **重新整理玩家**：按 F5。地圖、迷霧形狀、token 位置立刻出現，和 GM 一致。
3. **重新整理 GM**：按 F5。GM 畫面還原同樣的地圖、迷霧、token 與格線。
4. **GM 沒開時開玩家**：關掉 GM 視窗，再重新整理玩家視窗。玩家仍顯示剛才的地圖、迷霧與 token。重新開 GM 視窗後，兩邊照常同步。
5. **換地圖**：GM 上傳另一張地圖。玩家換成新地圖、迷霧全蓋。重新整理玩家，仍是新地圖。
6. 先攻、擲骰、HP、亮度調整、平板版面照常可用。

### G. 本機暫存與離線：兩台裝置（room）

準備：同 B。GM 用筆電、玩家用平板或手機，網址都用平常的 **https 網址**（Service Worker 需要；區網 http 位址只能測第 1、3、4 步）。玩家裝置若是筆電，可按 F12 開「開發人員工具」觀察。

1. **重新整理不再下載圖片**：
   - GM 上傳一張大地圖（例如 3MB 以上）與 2 個 token，擦幾塊迷霧。
   - 玩家第一次開 `…/pl.html?room=cachetest1`，等地圖出現。Console 會看到「從 Firebase 下載（x MB）」。
   - 玩家按重新整理：地圖、迷霧、token 幾乎立刻出現。Console 只看到「從本機暫存載入…不需下載」，沒有「從 Firebase 下載」。
   - 也可以到 Firebase Console 的「用量」頁比較：多次重新整理，下載量幾乎不增加（用量頁約有 1 小時延遲）。
   - Firebase 走 WebSocket 連線，開發者工具「網路」頁籤不會一筆一筆列出下載；要看的話點選 `.firebasedatabase.app` 那一列，切到「訊息」查看。
2. **斷網後重新整理**：
   - 玩家開著頁面時關掉 Wi-Fi（手機請一併關掉行動數據），再重新整理。
   - 畫面顯示斷線前的地圖、迷霧與 token；約 4 秒內右下角變成紅點「離線中，顯示的是暫存畫面；恢復連線後會自動更新」。
   - 打開 Wi-Fi，不用重新整理：右下角回到「已連線」，畫面自動更新到最新。
3. **玩家離線期間 GM 擦霧、移動 token**：
   - 玩家關掉 Wi-Fi（頁面開著）。
   - GM 擦掉一大片迷霧（多畫幾筆，超過 200 筆也可以），移動 2 個 token，再新增 1 個 token。
   - 玩家打開 Wi-Fi：迷霧形狀、token 位置與數量都和 GM 一致。
4. **GM 斷線期間的操作**：GM 關掉 Wi-Fi，擦霧、移動 token，**不要關分頁**。打開 Wi-Fi 後，玩家畫面跟上 GM。
5. **GM 換新地圖、刪 token**：
   - 在 Firebase Console 打開 `rooms/cachetest1/imageIndex`，記下目前地圖的雜湊（也就是 `rooms/cachetest1/map` 的 `hash`）。
   - GM 上傳另一張地圖，再刪除一個 token。
   - 玩家拿到新地圖，被刪的 token 消失。
   - 約 1 分鐘後重新整理 Firebase Console：`imageIndex` 與 `images` 中舊地圖、被刪 token 的雜湊都已消失；新地圖與其他 token 的圖片還在。
6. **清除 room**：GM 按「清除目前 room 暫存」。玩家畫面自動重新整理成空白，之後再重新整理也不會出現舊地圖。

- 網頁由本機伺服器 `http://127.0.0.1:8765` 提供，以 Chrome 無頭模式加自動化腳本，連實際 Firebase 測試房間（房間名稱 8 個字元，測完即清除）驗證：
  - room：玩家重新整理不下載圖片（2.1MB → 2.6KB）、玩家斷線期間 GM 擦霧超過 200 筆觸發壓縮並移動 token 後重連一致、全開／重設同步、清除房間後玩家清掉暫存、GM 重新整理不下載圖片。

  - GM 在同步服務載入失敗時擦霧、移動與新增 token，中途重新整理後恢復網路，修改正確補送給玩家。
  - 換地圖與刪 token 後，Firebase 上沒人用的圖片在保留期後刪除。
  - olroom 與不帶房間參數的畫面：雙視窗同步、重新整理還原、GM 視窗關閉時玩家仍能顯示。

### H. LAN 模式：GM 筆電＋兩支玩家手機（lanroom）

準備：GM 筆電執行 `start-lan-server.bat`；兩支手機與筆電連同一個 Wi-Fi 分享器或 Android 熱點。**拔掉分享器的對外網路，或關閉熱點手機的行動數據**，確認完全沒有網際網路。

1. **加入**：筆電開 `http://127.0.0.1:8765/gm.html?lanroom=lantest01`，右下角「LAN 模式・已連線・玩家 0 人在線」。按「玩家 QR Code」：對話框列出筆電的區網 IP，QR Code 與網址是 `http://筆電IP:8765/pl.html?lanroom=lantest01`，網址裡沒有 `127.0.0.1`／`localhost`／金鑰。兩支手機掃描加入，GM 顯示「玩家 2 人在線」。
2. **地圖與迷霧**：GM 上傳大地圖（例如 8000×6000 PNG）與數個 token，擦霧、補霧、矩形擦霧、全開、重設。兩支手機即時一致。
3. **Token**：GM 上傳的 token 鎖定，玩家拖不動；GM 解鎖後玩家 A 拖動，GM 與玩家 B 同步；玩家 A、B 同時拖不同 token 不互相覆蓋；玩家刪除未鎖定 token 後，其他畫面也消失、不會再出現。
4. **先攻與擲骰**：GM 新增先攻（含 HP），玩家只看到名稱與順序；從先攻表拖出 token；玩家擲骰，GM 看到「PL(暱稱)」。
5. **中途加入**：第三台裝置（或玩家重新整理）加入，立刻看到完整的地圖、迷霧、token、先攻。
6. **斷線重連**：玩家 A 關 Wi-Fi 約 10 秒，右下角變成「已斷線，正在重新連線」；期間 GM 擦霧、移動 token。玩家 A 開回 Wi-Fi 後自動恢復並一致。
7. **GM 斷線時操作**：在伺服器視窗按 **Ctrl+C** 停止伺服器（GM 頁面在筆電本機，關 Wi-Fi 不會讓它斷線）。GM 移動 token、擦霧，右下角顯示「N 筆修改會在重新連線後送出」；也可以重新整理 GM 頁面（`127.0.0.1` 網址有離線快取）。重新執行 `start-lan-server.bat` 後，玩家畫面收到這些修改。
8. **伺服器重啟恢復**：停止並重新啟動伺服器，所有人自動重連，房間內容不變。
9. **房間隔離**：另開 `pl.html?lanroom=lantest02`，看不到 lantest01 的任何內容。
10. **權限**：玩家手機開 `http://筆電IP:8765/gm.html?lanroom=lantest01`，會要求輸入 GM 管理金鑰；取消後右下角顯示「需要 GM 管理金鑰」，這個畫面的任何操作都不會同步給別人。輸入伺服器視窗的金鑰後才以 GM 身分加入（兩個 GM 畫面都出現「另一個 GM」警告）。
11. **外部請求**：筆電用 Chrome 開發人員工具的「網路」頁籤觀察 GM 頁，只有筆電本身的網址，沒有 `gstatic.com`、`firebaseio.com`、`firebasedatabase.app`、Cloudflare 等請求。
12. **參數衝突**：開 `gm.html?room=lantest01&lanroom=lantest01`，畫面顯示「網址同時包含多種同步模式」並停止同步。

## 部署與安全

這個專案是純前端靜態網站；若自行部署並啟用 Firebase 同步，請先檢查資料庫規則與房間存取權限。

Cloudflare Workers 的部署設定在 `wrangler.jsonc`（整個資料夾當靜態網站發布）。`.assetsignore` 排除 `node_modules`、LAN 伺服器（`server/`、`lan-server.js`）、測試與隱藏檔；Cloudflare 建置時會先依 `package.json` 安裝套件，沒有排除的話 `node_modules` 裡的大檔案會超過 Workers 單檔 25 MiB 上限而部署失敗。新增網頁要用的檔案不必改設定，新增只給伺服器用的檔案時再加進 `.assetsignore`。前端 Firebase `apiKey` 並不等同私密伺服器金鑰，也不能取代資料庫安全規則。
